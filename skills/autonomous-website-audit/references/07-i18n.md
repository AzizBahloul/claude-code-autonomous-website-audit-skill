## Find the supported languages

Read the i18n config:

- **next-intl:** `i18n/routing.ts` or `i18n.ts` (`locales`).
- **next-i18next:** `next-i18next.config.js`.
- **react-i18next:** the `i18next.init` resources.
- **vue-i18n:** `createI18n`.
- **Angular:** the `i18n` section of `angular.json`.
- **Django:** `LANGUAGES` plus `locale/`.
- **Rails:** `config/locales/` plus `available_locales`.
- **Laravel:** `lang/`.

Note how the locale is chosen: a path prefix (`/fr/...`), a cookie (`NEXT_LOCALE`), a
subdomain or the `Accept-Language` header. If the site has only one language, still check
hard-coded copy and number formats, then mark the layer done with a note.

## Catalog check

Run this once per run, and again after you change a catalog:

```bash
python3 ${CLAUDE_SKILL_DIR}/scripts/i18n_check.py . --scan-code src
```

It reports missing, extra, empty and untranslated keys and placeholder mismatches per locale,
plus `t('key')` calls that have no entry in the catalog.

## This page's strings

In the page and its components, find user-visible text that is not translated:

- JSX or template text nodes;
- `placeholder`, `aria-label`, `title` and `alt`;
- toast, error and confirm messages;
- `<title>` and meta tags;
- `Intl` labels;
- strings returned by the backend and shown as-is: validation errors, enum labels, emails.

Move each one into the catalog for EVERY locale, reusing an existing key when the meaning is
the same.

## Render in every locale

Capture the page once per locale, at all three widths, for the main role:

```bash
node ${CLAUDE_SKILL_DIR}/scripts/crawl.mjs capture --base http://localhost:3000 --path /fr/dashboard \
  --storage .website-audit/auth/coach.json --locale fr --out .website-audit/shots/i18n
```

Use the path prefix, cookie or header the site actually uses. Then tile the captures and view
them. Check for:

- `rawKeys` and `unfilled-placeholder` findings in the report;
- copy left in the default language;
- longer languages (German, French) overflowing buttons, tabs and table headers;
- right-to-left languages (Arabic, Hebrew): `dir="rtl"` on `<html>` (the report's `dir` field),
  a mirrored layout, logical CSS properties (`ms-*`/`me-*`, `start`/`end`), and icons that
  point the right way.

## Number, date and plural formats

Grep the page's code for formatting that ignores the locale:

- `toFixed(` followed by a hand-written `%`, `$` or `€`;
- `toLocaleString()` or `toLocaleDateString()` with no locale argument (they use the browser's
  locale, not the app's);
- date strings assembled by hand, and hard-coded decimal or thousands separators;
- `count + ' items'` or ternary plurals instead of ICU or the library's plural rules;
- sorting with `<` instead of `localeCompare` or `Intl.Collator`.

Use the i18n library's formatters or `Intl.NumberFormat`, `Intl.DateTimeFormat`,
`Intl.RelativeTimeFormat` and `Intl.PluralRules` with the active locale. Check the result on
screen in each locale: `12,5 %` in French, `12.5%` in English, and the right currency symbol
and position.
